# 18 · Shared 11 to 13 (briefly): what they need from everything before

Not researched in depth (the brief: "only so nothing earlier blocks them"; decision 0059: steps after the rethink are written down, not planned in detail). For each: what it depends on, and the rules earlier phases must keep so it isn't blocked.

## Shared 11: scripting, full export, Git and mods

**The scripting window** (LustScript and Lua through Luau, calling the same commands as the built-in tools, with undo, a sandbox and time limits).
- Depends on **every editor tool going through named, undoable commands** (the shell's `ShellCommand` table, the document's reversible edits, decision 0022). **Rule for earlier phases:** each new tool (tile decoration, scatter, stamps, paths, the ground's sculpt and paint, rooms on the world map, data tables, cutscene and behaviour editors, material graphs) exposes its operations as commands with typed arguments, not only as mouse handling. Cheap if done as each tool is built; expensive to retrofit.
- Depends on the sandbox and time limits (exist for game code: `script::luau`).

**The full export** (finished games for Windows, the game's own Rust built in, Lust compiled to Rust, an installer, Build-and-Play).
- Depends on **Lust's Rust output matching Luau** (decision 0028's comparison tests). **Rule:** every new engine call and engine-run Lust feature (tweens, timers, `on enter`/`leave`, test blocks, weighted random, generated per-asset classes) gets a test that runs it both ways.
- Depends on the asset pipeline packing every new asset kind (region files, recipes, materials' compiled shaders, effects, music, translations, navmesh caches). **Rule:** each new kind declares whether it ships, how, and what is cache (rebuildable, not shipped).
- The installer: Solis's own uses Inno Setup (decision 0043); reuse.

**The Git panel and the level merge tool** (decision 0006).
- **Rule:** every new text format keeps "one block per thing, stable random IDs, fields in a fixed order" (decision 0020) so it merges: tables, world files, decoration rules, paths, cutscenes, behaviours, materials, effects, weather, music. Binary data (ground regions, baked probes, flipbooks) goes through Git LFS with **locking** (decision 0116 already made region files per 256 m so they lock separately).
- Prefabs (R5) and overrides must merge per field.

**Mods** (players change and add with LustScript, the same sandbox).
- Depends on a **stable game-code interface** (rule 24's guarded snapshot) and on data files being Lust (decision 0081): mods add or override data files and code. **Rule:** keep everything a game reads at run time behind asset IDs and project names, never hard paths.

## Shared 12: netcode (decision 0005)

- **Determinism is the dependency.** Every game-state feature added in these phases must be deterministic on any core count and **any PC**, checksummed and saved: tile and ground edits (fixed-point brushes), pathfinding and navmeshes (pure functions of the start-of-tick world), triggers, timers, tweens (decision 0106's cross-core ordering gap must be closed: `05-shared-3.md`), behaviour and cutscenes, weather choice, rooms, spawning with values, pools (new IDs on reuse). **Output only** (never in game state): effects, light, sky, UI, music, shake, squash, debug drawing.
- **Cross-PC check:** light.md recommended a CI job playing a recorded game on Linux and Windows and comparing checksums (decision 0102 paused Linux checks; Windows-only builds still differ by CPU: FMA, `sin`/`exp` libraries). **Recommended:** add it before Shared 3 (Lust tweens and noise bring transcendental maths into game state).
- **GPU-made data must never be game state** (Open worlds' far levels are fine because they're drawing only).
- Rooms (Shared 6) and streaming affect what each peer simulates: lockstep needs every peer to load the same rooms at the same tick.
- Saves are snapshots (decision 0038): keep every new state in saves, which netcode's join-in-progress will reuse.

## Shared 13: Solis 0.1

The flagship space battle over the network (lockstep), docs, templates, release. Depends on: effects (Shared 8), the benchmark (exists), lockstep (Shared 12), and **docs/templates** for 2D (the 2D sample, 2D 2) and 3D (the light showcase, 3D 2). The space battle needs no skeletal animation or ground; it does need projectile hits as game state (`10-shared-8.md`: still not built).

## What looks risky for these later phases now

1. **Tween done-block ordering across cores** (decision 0106): a determinism hole already in the engine.
2. **Lust's own `Random` isn't seeded by the game** (0106): game code using `Random[1, 6]` breaks replays and lockstep; add a Problems warning (or make Lust's `Random` use the host's seed, asked of Lust).
3. **Editor-only tool code paths** (no commands) would block the scripting window.
4. **Binary formats** without LFS locking would block team work.
