# Tools 1: shape brushes and world sculpting

**Status:** planned on 2026-11-13 from the project lead's answers; the mock-ups are approved (below). B1, B2, B3 and B4 are built (see "As built" below). Decisions [0108](../decisions/0108-shape-brushes-and-sculpting-come-next.md) (the order) and [0111](../decisions/0111-tools-1-brushes-and-ground.md) (what the tools are).

## What the project lead asked

On 13 November 2026: "having brushes to be able to create shapes in engine is important. What I want is to be able to press B to open the brush list. Continuously pressing B traverses the list downwards, and space confirms selection. We also need a world sculpting tool, and I need all of these changes to be performant."

Their answers, the same day:

| Question | Answer |
| --- | --- |
| What a brush is | Shapes edited point by point, edge by edge and face by face, with extruding, as level editors of the brush kind do |
| Placing one | **Draw it out:** drag on the ground for its footprint, move the mouse up for its height, click |
| The brush list | **B** over the 3D or 2D view opens it, each **B** moves down, **Space** confirms while it's open, **Esc** closes; with a tile map picked, B stays the tile Brush (decision 0108) |
| Editing a brush's insides | **Tab** toggles editing the picked brush; while editing, **1** points, **2** edges, **3** faces |
| Extruding | **E**, then move the mouse and click (Esc or right-click gives up); **and** Shift + drag on the move gizmo |
| What sculpting shapes | A **ground with caves and overhangs**, not a height map alone |
| The sculpting mouse | **Left-drag adds, Ctrl + left-drag digs, Shift + left-drag smooths**; **[** and **]** the brush's size, **Shift + [** and **]** its strength |
| The ground's look | **A setting per ground**, so each game picks its art style: Smooth (like clay), Blocky (cubes), Sharp (smooth, with hard edges at cliffs and cuts) |
| Painting materials | **In this phase too** (grass, rock, sand…) |
| Speed | Everything fast, with scale cases (decision 0108) |

## Two phases

Tools 1 is too big for one phase (CLAUDE.md: two to six milestones), so it is two, each with its own gate.

### Tools 1a: brushes

| Milestone | What it gives |
| --- | --- |
| **B1 The shape core** | Aventail's polygon mesh (n-sided faces with full adjacency, stable IDs, operations as pure functions; decision 0007 lets its code be copied in) as a new `mesh` crate, trimmed to what brushes need, with Solis's limits on everything it reads. Generators for the list's shapes (box, ramp, wedge, cylinder, stairs, arch, sphere). A **Brush** component holding its mesh in the area file (a format change: version raised, upgrader, fuzz test; rule 23). Drawn as a mesh made again only when it changes; solid through a triangle-mesh collider (physics gains them). |
| **B2 The list and drawing out** | B, Space and Esc as answered; drawing the footprint on the grid (snapping, sizes shown), then the height, then click; one undo step; the brush in the Area list like any entity. |
| **B3 Editing the insides** | Tab, 1, 2, 3; picking points, edges and faces (click, Ctrl + click, box); the move, rotate and scale gizmos on what's picked; every change through the command stack, so undo works and the area file stays valid. |
| **B4 Extrude and shaping** | E then move and click, and Shift + drag on the gizmo; the other shaping actions the approved mock-up shows (Inset, Split, Delete). A brush made inside out or with holes is refused or repaired, never saved broken. |
| **B5 Materials, speed, the gate** | A material per face; scale cases (10,000 brushes in an area; editing a 5,000-face brush; drawing out with 10,000 brushes around); the manual. **Gate:** a small level blocked out with brushes, edited and extruded, played (walked on, collided with), saved and reopened. |

### Tools 1b: the ground

| Milestone | What it gives |
| --- | --- |
| **G0 The study** (rule 22) | Competing ways to store and draw a ground with caves, built and measured against each other in `docs/reports/`: storage (fixed chunks of voxels; sparse chunks that store only the surface; an octree), and drawing each look (Smooth: surface nets, marching cubes; Sharp: dual contouring, or sharp features added to surface nets; Blocky: cube faces merged). Measured at the scale target: one brush stroke from mouse to screen, a chunk made again, memory and file size per square kilometre, triangles drawn, collision per chunk. The best of each goes into decision records. |
| **G1 The ground, Smooth** | One ground per area, in chunks, its own file (format, version, fuzz test); drawn in the Smooth look, chunks made on workers, never on the frame; solid to physics chunk by chunk; saved and loaded. |
| **G2 Sculpting** | The **HOME TOOLS · Ground** tab: Add, Dig, Smooth, Flatten; the brush's size, strength and falloff; the mouse and keys as answered. A stroke is one undo step, saved when let go; only touched chunks are made again. |
| **G3 Blocky and Sharp** | The other two looks, chosen per ground, switching at once. |
| **G4 Painting** | Materials painted with the same brush, from a palette on the shelf; blended where they meet; drawn without stretching on steep and overhanging ground. |
| **G5 Speed, game code, the gate** | Scale cases (the biggest ground the scale target names, sculpting it, walking 2,000 units over it); game code asking the ground questions (its height, a ray against it), following the game-code rules (decision 0065); the manual. **Gate:** a level of brushes on a sculpted, painted ground with a cave, in each look, played, saved and reopened, at the scale check's targets. |

### As built

- **B1** (2026-11-13): the `mesh` crate (Aventail's mesh trimmed to the n-gon mesh, topology, attribute layers, builder, triangulation, shading, primitives, extrude and inset), the seven shapes (`mesh::Shape`, settings within limits), the `Brush` component (made as, Solid, the mesh as three lists of numbers; counts checked before anything is made; area files' version 3), brushes cut into flat triangles only when the document's brush revision changes and shared when equal, solid as a still triangle surface in physics, and **Create › More › Box brush** until B2's list. Left for B2 onward: the list and drawing out (the other shapes can't be added from the editor yet); changing **Made as** doesn't rebuild the mesh; a damaged brush reads as empty without a Problems entry; each face's material slot is saved but every face draws the plain material (B5); an undo or redo looks at every brush's values again (10,000 boxes took 94 ms in a debug build; release not yet measured), and a brush deleted then brought back by undo is cut into triangles again.

- **B2** (2026-11-14): the brush list (`editor::brushing::list`): **B** over the 3D or 2D view opens it beside the pointer (not with a tile map picked: B stays its Brush), each B moves down and wraps, **Space** takes (before the search's), **Esc** or a click elsewhere closes, a click on a row takes; **Home › Create › Shape** (its key small beside it, lit while in use) opens the same list and replaced Create › More › Box brush. Drawing out (`brushing::draw`, `brushing::ghost`): the footprint dragged on the grid (Ctrl free), starting on top of the brush or model box under the pointer (a narrow test once, `brushing::surface`) or the ground; let go, the height up a line standing on its middle (up the screen when looking straight down), click; Esc or a right-click under way gives up; a footprint or height of nothing makes nothing and the status bar says why. In the 2D, Front and Right views the footprint is in the view's plane and letting go makes it, one grid step deep. Each brush is one undo step, named after its shape (Box_01, the highest number plus one), picked, placed as Create's buttons place things (`spawn_selected`); the Area list shows its shape's icon and name, as the mock-ups draw it. The steps at the top of the view, the keys at its foot, the sizes beside the edges, the status bar and the Hints card say what's happening. The counts the list starts with: Cylinder and Sphere 16 sides, Arch 12 pieces, Stairs a step per 25 cm; the Ramp and Stairs climb the longer side from the drag's start. From B1: **Made as** makes the mesh again at the brush's size in the same undo step, and a damaged brush is in the Problems list with why. Scale case: drawing out among 10,000 brushes (`scale_check_drawing_out_among_10000_brushes`). Left for B3 onward: editing the insides, extrude, materials; the choices taken while the project lead was away (the list's order and counts, what a drag starts on, the 2D view, the side views, snapping always to the grid's step) are on their morning list.

- **B3** (2026-11-14): editing a brush's insides (`editor::brushing::{edit, parts, reshape, edit_draw, card}`, `workbench_brush_edit.rs`, `workbench_brush_parts.rs`, `shell/ribbons/brush.rs`). **Tab** with one brush picked starts it and ends it (and Done); **1**, **2**, **3** pick points, edges or faces (switching keeps the pick as the new mode's parts); the keys act only where the area has them, and not with a tile map picked (its Tab) or over the UI canvas (its 1, 2, 3). HOME TOOLS · Brush comes to the front: Points, Edges, Faces and Done (as large buttons with their keys, where the mock-up draws a segmented row), Extrude, Inset, Split, Delete and Material unfinished, Solid, Snapping (Grid, Angle). Picking: a click (lit before), Ctrl + click toggles, a box on empty space (through the brush), a click on empty space clears; only the edited brush is tried (its box, its faces' boxes, then triangles). The gizmos on the picked points' middle, World or the brush's own axes, snapping and Ctrl as for entities; each drag drawn on the brush's own copy (a passing model, uploaded alone), checked when let go (`mesh::check_moved`: folded, flattened, passing through, only the faces touching what moved) and written as one undo step of the points list, or put back with why in the status bar. The other entities dimmed by the renderer (`Shading::focus`), the brush's edges and dots drawn over the view, the text at the top and keys at the foot, the status bar and Hints. The Brush card: Made as, Size (typed: stretched about its middle, one step), Material (unfinished), Solid with its note, the three counts and what's picked. Choices taken while the project lead was away (on their morning list): a break refused; clicks reach only the edited brush and the Area list ends editing; Delete and Backspace do nothing yet; Made as replaces edits and says so; shared parts move together; the 2D view edits too; Esc clears the part pick and Ctrl + A picks every part while editing; a box picks through the brush. Small fixes: a picked brush outlined by its edges; the unfinished large buttons widened to their word ("Trigger zone"); Model's "Ready-made shapes" (a stand-in for brushes) is now "Shape brush…". Scale case: `scale_check_editing_a_5000_face_brush_among_10000_brushes` (release, this machine: the frame that starts editing 8.2 ms in the test window, 3.5 ms of it the editor's own work, which is what's judged, the rest the test window's accessibility tree and words laid out anew, as any frame that changes the screen pays; hovering 3.9 ms a frame, finding the part 0.06 ms; a box over all 5,046 faces 0.2 ms and its frame 6.7 ms; dragging 1,073 faces 5.2 ms a frame; letting go 6.9 ms and the next frame 5.7 ms; target 8 ms). To get there, an edit made only of Brush fields no longer works out the view, the world matrices or the files' users again (`Document::placed`), Problems look again only when which brushes are damaged changes, and the drag's last model is kept as the brush's (never read back from its values). Left for B4 onward: extrude and the shaping actions, deleting parts, materials; passing through is checked only between faces that share no point.

- **B4** (2026-11-14): extrude and shaping (`editor::brushing::{pull, shaping}`, `workbench_brush_shaping.rs`; `mesh::{split, merge, whole, repair}`). **E** (or Extrude) with faces picked: the mouse pulls the new part out along the faces' way (read along that line through the pick's middle, or up the screen when the camera looks along it), snapped to the grid's step (Ctrl free), a click keeps it, Esc or a right-click gives up; the distance beside the new part on a measuring line, "Extruding 1 face · 2.00 m" at the top, the keys at the foot, the status bar and Hints say what's going on; touching faces go out together, straight along their average facing, others each their own way; pushing in is allowed. **Shift + drag** on a move handle extrudes the picked faces by nothing, then moves their copies. Edges extrude only on an open side, so on a closed brush E is refused with why. **Inset** the same way, the width growing as the pointer moves away from where it began. **Split**: two points on one face cut it; edges get their middles; faces are cut across their middle so their longer sides are halved. **Delete** (and Delete or Backspace while editing; outside editing they delete entities as before): points and edges go and the faces around them merge, a point left in the middle of a straight side going too; touching faces merge into one; a lone face is refused (a hole). Every result is checked by `mesh::check_whole` around what changed (closed, facing out, room inside, four faces or more, not passing through) and kept as one undo step of the brush's three lists, or refused with why. The ribbon's four buttons are built, each greyed with why (Extrude lit with E while in use). A brush read open or inside out is mended as it's read when simple and safe (faces turned round; a hole with one flat border filled), else drawn as read and named in Problems (`ProblemKind::OpenBrush`). Choices taken while the project lead was away are in its pull request. Scale case: `scale_check_shaping_a_5000_face_brush_among_10000_brushes` (release, this machine, on a day B3's own case measured letting go 11.2 ms against its 6.9 before: extruding 1,073 faces 6.3 ms a frame, starting it 24.6 ms, letting go 17.1 ms and the next frame 9.2 ms; insetting them 7.8 ms a frame, letting go 16.3 ms; a delete merging 100 faces 23.0 ms, 16.1 of it the delete, and the next frame 4.6 ms; target 8 ms). Pulling is within the target; letting go and the delete are one-off frames over it, most of them writing the brush's three lists and cutting its 5,000 faces into triangles again (the whole check itself is 2 to 4 ms), left for B5's speed work: an edit that rewrites only the part of a brush that changed. Left for B5: materials per face, the Material buttons, the remaining scale cases and the gate; extruding edges is possible only on open brushes, which B4 never makes.

## Still to settle (asked when their milestone starts)

- Which shapes are in the list at first, and their standard sizes: taken as recommended for B2 (all seven, the mock-up's order; sizes from drawing out), on the project lead's morning list.
- What game code may change on a ground while playing (digging in a game is a game's feature; the engine offers the calls).
