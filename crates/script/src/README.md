# script/src

Game code (decision 0028): a project's Lust, checked and turned into Lua by the Lust compiler, run in Luau while the game plays, together with the game's Lua and Rust components. Game code is untrusted: every call has a time limit, memory is capped, and code that misbehaves ends in a failure, never a frozen editor.

**Start reading at** `lib.rs`, then `runtime.rs` (one Luau running components) and `game.rs` (shared across every core).

## Loading code

| File | What it does | Main items |
| --- | --- | --- |
| `lib.rs` | Lists the modules and what the crate offers; checks save-slot names. | `valid_slot` |
| `code.rs` | Gathers every `.lst` and `.lua` file in a project's assets within limits and checks and compiles it, on a worker; finds uses of renamed natives' old names, for warnings; puts the fields' hints on the schemas, with their mistakes for Problems (`Compiled::hint_problems`). | `Code`, `Compiled`, `CodeProblem`, `gather`, `check`, `compile`, `try_compile`, `check_unfinished`, `renamed_uses` |
| `check_turns.rs` | Checks of the code take turns, each on a thread with a large stack and a time limit; one that never finishes is given up on and kept, and no other starts until its thread ends (the author is told which check that was and what changed since). Tests in `check_turns_tests.rs`, with a stand-in for a compiler that never finishes. | `NotStarted` |
| `describe.rs` | The engine described to Lust: the `solis/*.lst` files a project gets, made from the list of native methods so they always match (decision 0016), plus the ready-made components in [`kit/`](kit/README.md). Natives renamed on purpose keep their old names for a while (`RENAMED`). | `NATIVES`, `Native`, `RENAMED`, `descriptions` |
| `old_names.rs` | The project's names game code had before decision 0118 (`Assembly`, now `Prefab`), each use a mistake naming the new one, found before Lust is asked (a straight switch, as for R2). | `RENAMED_STATES` |
| `project_names.rs` | The project's own names as Lust states (decision 0065): `solis/project.lst`, written by the editor whenever the project's files change, so game code names a prefab as `Prefab.Ships.Fighter`, never as text; a typo is a mistake before the game runs. Folders become options inside options; a picture's Atlas Crop crops are options inside it, and the project's levels are `Level` (decision 0127). `states_in` reads a project file's states back, for Lua fields of their kinds. | `Names`, `project_file`, `option_of`, `path_of`, `states_in`, `States` |
| `animator_code.rs` | Each animator's own Lust file (decision 0078): `farmer.solanim` gives `solis/animators/farmer.lst`, a state of its graph's states and a class with a method per thing code can set or ask (`setMoving(on)`, `swing()`, `current()`, `jumpTo(...)`), whose bodies call the engine's `Animators` object. | `AnimatorNames`, `animator_file`, `class_names` |
| `map_code.rs` | Each tile map's own Lust file (decision 0079), like the animators': states of its layers, its tileset's terrains and each choice value's options, and a class with a method per thing code can ask or change (`terrain(layer, x, y)`, `setGrowth(x, y, to)`, `width()`...), whose bodies call the engine's `Maps` object. | `MapNames`, `map_file` |
| `table_code.rs` | Each data table's own Lust file (stage 1, decision 0128): a state of its rows' IDs (`Item`), a state for each choice column (`ItemRarity`), a class of one row whose fields are locked (`ItemRow`) and an object for the table (`Items`) with the natives `row(Item which)` and `rows()`; tables whose names clash with another's or the engine's are left out with a note. Tests in `table_code_tests.rs`. | `TableNames`, `table_file`, `table_files`, `named` |
| `text_code.rs` | The game's text as game code reaches it (stage 1, translations; decision 0131): the keys and languages for `state Text` and `state Language`, and `solis/texts.lst`, a method per line with values on its group's object (`ShopText:welcome`); lines whose methods can't be made are said. Tests in `text_code_tests.rs`. | `TextNames`, `Method`, `texts_file`, `FILE` |
| `texts.rs` | The game's text while it runs: `World_text` and each line's method, lent from functions each Luau makes once per text and language (`Lent`, `MAKE`), a misspelt key stopping at the game code's line with the nearest. Tests in `texts_tests.rs` (Lust, Lua and Rust; a misspelt key; a value left out; the language changed while playing; a table's translated cells). | `Lent` |
| `tables.rs` | Data tables while the game runs: `Tables`, the project's tables by the name game code calls each, with their number for saves and recordings (`hash`); each Luau's natives for them (`Lent`, `MAKE`: a row made into Lua once and kept, a new list of all of them for `rows()`, made again when the tables change), and Rust's `TableRef` and `RowRef`. Tests in `tables_tests.rs` (Lust, Lua and Rust; a misspelt row or column; a table changed while running; the lookup's speed). A translated column's cells are read in the player's language (`RowRef::translated`, and Lua's rows made again when the language changes). | `Tables`, `TableRef`, `RowRef` |
| `interface.rs` | Everything game code can call as one text, compared by a test with `docs/game-code-interface.txt`, so the interface changes only on purpose (Phase 8, C3). Its Lua names are asked of a real Luau with the natives lent, so it lists what Lua can reach. | `snapshot` |
| `lust_program.rs` | The game's Lust loaded into Luau, with its components' fields, schemas and events, and its game-wide objects. | |
| `objects.rs` | The game-wide objects (decision 0080): each passed Lust `object`'s fields moved into a guarded store, so only the objects' updates change them; their kept values read and written for other cores, saves and new code. | `ObjectValues` |
| `lua_components.rs` | Components written in Lua (decision 0003): each `.lua` file in the assets makes components with `component`. A field's fifth entry is its hints table, and a kind that's one of the project's names (`"Sound"`) takes its options from `solis/project.lst` (decision 0127). | |
| `field_hints.rs` | Field hints (decision 0127): the words (`range`, `step`, `unit`, `tip`, `group`, `multiline`, `hidden`) read from a Lust comment's `[ ]` or a Lua table, put on a field's `reflect::Hint` the same way for every language, with a sentence for each mistake; a starting value outside its range. Tests in `field_hints_tests.rs` and `field_hints_code_tests.rs`. | `read`, `from_lua`, `apply`, `outside_range` |
| `hint_comments.rs` | A Lust field's hints from the comment after it (`float speed = 4.0; -- [range 0 10]`), found with `level::lust_fields`, put on the compiled schemas with each mistake's line (`Compiled::hint_problems`); and a field of the project's names given its picker (`Offer::Names`). | `put_on`, `hint_in` |
| `screens.rs` | Game screens (decision 0087): the files in `ui/`, their own program (an entry opening each, and `solis/screen.lst` with `Ui` and a reader per Lust component), and `Screens`, which runs it in a runtime of its own, lends the readers through a `ScreenReader`, and reads each view's tree for `ui` within one budget for the whole view (`Reading`: pieces, styles and bytes of text, so nothing game code hands over is copied without a count); `pictures_named` finds each `image "…"` written out in them (decision 0089), with its line, and `text_marks` the icons and markup mistakes of each `text "…"` and `button "…"` (stage 1, text effects); `ScreenCode::sources` keeps their files for the UI editor, and `events_named` lists the game's events for its buttons. Tests in `screens_tests.rs`, and in `screens_reading_tests.rs` for reading a view's tree: long texts, style lists shared or holding themselves, lists of anything else, the budget's edges, and a sweep of made-up trees. | `ScreenCode`, `Screens`, `ScreenReader`, `readers_file` |
| `test_support.rs` | What other crates' tests need of game code, with the `test-support` feature only (TEST-02): games and compiles given limits no busy machine reaches, game by game. | `unhurried`, `calls_unhurried`, `compile_unhurried` |
| `settings.rs` | The player's settings (decision 0091): text size and UI size (`Screens:`), fullscreen and the window's size (`Window:`), kept in their ranges, and the usual window sizes. Not game state: not in saves, recordings or the checksum. Tests in `settings_tests.rs`. | `PlayerSettings`, `Setting` |
| `rust_component.rs` | Components written in Rust by a game, running in the same ticks and order and sending the same events as Lust's. | `RustComponent`, `Context` |

## Running it

| File | What it does | Main items |
| --- | --- | --- |
| `luau.rs` | The Luau game code runs in, made safe: time limits per call, per tick and per load, a memory cap, no access to files, and no way to another file's globals or Solis's own (`sandboxed_lua` takes out `require`, `loadstring`, `getfenv` and `setfenv`; Solis's own Lua is all made in `Luau::new`, before any game code). | `TIME_LIMIT`, `TICK_LIMIT`, `Clock` |
| `exact_maths.rs` | Game code's maths the same to the last bit on every PC (stage 1, the two-PC check): every Luau's `math` library gets `libm`'s sines, cosines, tangents and their inverses, `atan2`, `exp`, `log` (with a base), `log10`, `pow` and hyperbolic functions in place of the C library's, before anything runs, and Lust's runtime raises to powers with that `math.pow` where it used `^`. Tests in `exact_maths_tests.rs` (each function's bits pinned for a set of numbers, and the cost of a call measured, ignored) and `game_maths_tests.rs` (Lust's `Maths` in a running game). | |
| `interrupt.rs` | The watchman inside Luau that stops code running past its time limit, set cheaply (decision 0034). | |
| `runtime.rs` | One Luau holding the game's running components, one per entity and component name; swapping in new code while the game runs. | `Runtime`, `Failure`, `Ticked`, `Swapped` |
| `syncing.rs` | Making running components from the level's values, and passing on what changed or was set by hand. | |
| `ticking.rs` | One tick: the game-wide objects' `update`s, the tweens game code started (Lust's `tickTweens`), every component's `update` in one order, then delivering events. An `Order` also says which entity's code is running (who caused a sound). | `Order` |
| `events.rs` | Events between components: queued by `send`, delivered after the tick's updates in a fixed order, so a game runs the same way every time. | `Event` |
| `host.rs` | What game code can ask of the engine: the `Host` that answers the native methods, lent to Luau only while game code runs (`with_natives`). Tests in `host_tests.rs`. | `Host`, `NoHost`, `Shot` |
| [`natives/`](natives/README.md) | The natives themselves, one file per engine object, each lent under the key `describe::NATIVES` gives it. | |
| `native_values.rs` | A native as Lua calls it, reading each value it's given by itself, so one of the wrong kind is said in plain words by the call's name (`solis.World:say(words) wants text for words…`), and what's said when a native kept in a variable is called. Tests in `native_values_tests.rs`. | |
| `convert.rs` | Values between the editor's kinds (`reflect`) and how Lust keeps them in Luau (a `vec3` as a Luau vector, a `vec2` and a `colour` as tables). | |
| `game.rs` | Game code on every core (decision 0033): entities split into shards, each with its own `Runtime`, all seeing the world as it was at the start of the tick. | `Game`, `GameWorld`, `WorldView`, `Change` |
| `tag_view.rs` | Questions about tags for one tick (stage 1, tags): who carries which tag, and each tag's members in ID order, counted into a uniform grid over the ground when there are 32 or more, so `within` (nearest first, ties by ID) and `nearest` look only where their distance reaches; a big distance looks through the tag's list instead. Made once a tick and shared by every core. Across the ground in a 2D project, in 3D otherwise. Tests in `tag_view_tests.rs` (the grid held to a look through every member on a crowd and in a property test; the scale check). | `TagView` |
| `timers.rs` | Named timers (stage 1, decision 0125): what game code asks for (`Timing`, made whole ticks as a `Plan`), a timer's change and a finished one, timers' names' shape. | `Timers`, `Timing`, `Plan`, `TimerChange`, `Fired` |
| `timer_store.rs` | Where the timers wait: slots found by numbers (each name kept once), filed in buckets by when they're due in whole units of game time; a tick takes the buckets due off the front and puts their order right once. | `Timers::apply`, `advance`, `left` |
| `timer_text.rs` | The timers as a save keeps them (save version 11; from 12, each with the option it ends with), read within limits. | `Timers::write`, `read` |
| `timer_names.rs` | The game's timers' names, gathered from where its Lust starts them, for the `Timer` state in `solis/project.lst`. | `names_started` |
| `game_timers.rs` | A `Game`'s timers: kept beside its shards, due ones made `TimerFinished` events for the component that started each as the tick begins, starts and stops made at the tick's end, ended with their component, and checked against new code. | `Game::timers`, `set_timers` |
| `states.rs` | States that know when they start and stop (stage 1, decision 0126): Lust's rule for what a state ends (`still_in`), a state's change and what a sound started in one belongs to, Lust's runtime told about states without moving a line (`own_states`: its `setstate` stops the component's tweens of the options it leaves and tells Solis through a hidden native; its `tween` notes the running component's option), and Solis's own Lua that notes a Lust component with a state of its own as the one running (`RUNNING`), so a native finds its option as it starts a timer or sound (`started_in`). | `still_in`, `StateChange`, `Started` |
| `state_names.rs` | Which state each Lust component has of its own, read from where it sets its starting option, and the event it hears when that changes (`MoodChanged` for a `Mood`, declared by the game; declared otherwise, a mistake before the game runs). | `state_types`, `CHANGED` |
| `game_state_changes.rs` | A `Game`'s components hearing their own state change: each change kept as it lands, added up as the tick ends (the first `from`, the last `to`, none for a round trip), and waiting for the next tick's first round after the timers' events; what waits as a save keeps it, and in the checksum once something does. | `Game::states_waiting`, `set_states_waiting` |

## Tests

`timers_tests.rs` tests the timer store (exact ticks at any speed, pausing, rhythm, hours passed and jumped, order, saves and their fuzzing, and the scale case); `game_timers_tests.rs` a game's timers in Lust, Lua and Rust on one core and four. `runtime_tests.rs` and the `runtime_*_tests.rs` files test `runtime.rs`: events, swapping code, Lua components, hostile code that once froze or crashed the editor, where the runtime meets the rest (seams), and the speed fixes. `runtime_camera_tests.rs` tests cells at places and the kit's 2D follow camera. `runtime_reach_tests.rs` calls one native of every engine object from Lua, Lust and Rust, and fails when an object has no call to try. `game_tests.rs` tests `game.rs`: the same results on one shard or many, on games made by its `unhurried` and code from its `compiled` (time limits of an hour, so a busy machine can't cut a tick short and make two runs differ); `game_objects_tests.rs` its game-wide objects; `game_clock_tests.rs` random numbers and spawned entities whatever the game's speed (paused too); `game_tags_tests.rs` tags in Lust (`hasTag`, `addTag`, `removeTag`, `World:within`, `World:nearest`) on one shard or four, tag changes landing at the tick's end in order, and a misspelt tag failing the check; `game_tweens_tests.rs` what Lust alpha 67 brought (tweens, `vec2` and `colour` fields, in saves and on many shards, and the manual's tween example); `game_own_states_tests.rs` states that start and stop (timers, tweens and sounds ended with their option, options inside options, `keepStarted`, the event once a tick after the timers', saves, one core and four, Lua and Rust untouched, and the scale case); `states_tests.rs` the runtime's adjustment and reading which state a component has; `game_states_tests.rs` what alpha 74 changed (a state set with `=` runs, the same on any number of shards, and an old project setting one with `is` gets Lust's own mistake showing the `=` way). `luau_names_tests.rs` holds every name game code can see in `luau.rs`'s Luau to a list, the engine objects under `solis` among them, so a library update or a new engine object that adds one fails there. `manual_examples_tests.rs` checks the user manual's game-code examples (decision 0113): every Lust example through Lust with the engine's own description files and a stand-in project's names, and every Lua example compiled and started as Solis starts a Lua file, so an example can't call what the engine doesn't have.
