# level/src

The level document (decision 0019): entities with stable IDs, their components as plain values, changed only through reversible edits, which undo and redo are made of (decision 0022). Also how levels are written as text, and how modules are placed in them.

**Start reading at** `document.rs`, then `edit.rs`.

| File | What it does | Main items |
| --- | --- | --- |
| `lib.rs` | Lists the modules and what the crate offers. | |
| `document.rs` | The document itself: entities by ID, each with a name, a parent, a sibling order and components. | `Level`, `EntityData`, `Origin` |
| `edit.rs` | Reversible edits: every change is one, and applying one gives back its inverse, which is how undo works. | `Edit`, `EditError` |

Also what keeps a loop of parents (a damaged file) from doing harm: `Level::mend_loops` takes loops out as a level is read (one entity of each moved to the top level), and `Level::ancestors` is the one walk up through an entity's parents, which ends in a loop instead of going round. ## How the pieces fit

A `Level` holds the entities. The editor never changes it directly: it builds `Edit`s, applies them, and records the inverses as one `Step` in `History`. `text.rs` turns a `Level` into a file and back; `module.rs` expands placed modules on load and folds them back into overrides on save. No level in use has a loop of parents: reading a plain level and expanding a file both mend them (`tree.rs`), and no edit makes one. Component values are `reflect` values, described by the schemas in `builtin/`.
