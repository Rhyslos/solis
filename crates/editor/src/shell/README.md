# editor/src/shell

The frame round the editor, as the project lead's design has it ([decision 0099](../../../../docs/decisions/0099-the-g-layout.md); the design is `docs/design/g-layout/`, the plan `docs/plans/shared-1-ui-remake.md`). Five bands, top to bottom: the tab bar, the ribbon, the editor groups, the shelf and the status bar; on the File tab and an unbuilt screen, one page in place of the ribbon, groups and shelf. Docking is Solis's own and fixed ([decision 0104](../../../../docs/decisions/0104-docking-is-solis-s-own.md)): each tab's middle is a table, and today's panels are drawn inside it (`PanelViewer::draw_panel`) until each screen is rebuilt.

| File | What it does |
| --- | --- |
| `mod.rs` | `RibbonTab` (the ten tabs, and the two contextual ones, Tileset and Picture, each there while its file is open and called back to Library when it closes) and `Shell`, what the frame remembers between frames: the tab in front, whether the ribbon is collapsed or dropped, each tab's `Arrangement`, and where each panel was drawn last frame (for who has the keys, and for tests). It is the editor's one field for all of it (`Workbench::shell`). `Workbench::top` draws the tab bar, then the ribbon, the File page or an unbuilt screen's page; `middle` draws the groups and the shelf; `show_panel` brings any panel into view (its tab, its group's front or its shelf tab), which the search, the status bar, the contextual tabs and opening a file all use; Ctrl + Space folds the shelf (`shelf_keys`). |
| `workspaces.rs` | What each tab's middle holds: its groups' documents (`groups`) and its shelf's tabs (`shelf_tabs`, unfinished ones among them) with each shelf tab's columns (`ShelfTab::columns`), given what is open now (`OpenNow`: a running game, an animator, a tileset, a picture's crops, a clips file, a tile map selected); `Arrangement`, what a tab remembers of it; `home_of` and `tab_for`, where a panel is. Tests in `workspaces_tests.rs`. |
| `groups.rs` | The center: one or two groups side by side or stacked, their 30 px strips of document tabs (the area's with its **+** and right-click menu; a file's with its ×; a contextual tab's with ‹ Back to Library at the right), the divider and its drag; Animate's Sequencer page when nothing is open there. |
| `tab_drag.rs` | Dragging a document tab (answers 25 and 31): onto the left or right half of the center it stands alone in a group there; onto another group's strip the groups join; Esc puts it back. Kept in the tab's `Arrangement` (`alone`, `merged`, `Arrangement::arranged`) while the editor runs. |
| `shelf.rs` | The shelf: its bar (the grip and the bar's top edge set its height; the tabs; the tools of the tab in front at the right: the Console's filters, search, Clear and Copy, and Home's unfinished animation transport), and the front tab's columns, side by side or wrapped under each other. A column's header has its title, quiet words after it (the Assets column's folder), its panel's own tools (the Area column's search, Fold everything and ⋯) and a count; a column marked `own_header` (Properties on Home) draws its own header instead. |
| `status.rs` | The status bar: Ready or the code's mistakes, the branch (unfinished), the problems as coloured counts (click: the Problems tab), the context, what moves snap to ("Snap 0.25 · World"), the version, Restart to update. For three seconds after a click on an unfinished part, or after `status::tell` (Turn hints off), the context gives way to what was said. `Status` is what it says, kept apart from drawing for the tests. |
| `saved.rs` | `ShellState`, the frame as saved under its own settings key (`shell`): tabs by name, every field defaulted, `Shell::restored` repairing what it can; the Console's one-time note that a docked arrangement from before wasn't carried over. |
| `commands.rs`, `command_words.rs` | `ShellCommand`: the one table of what the editor can do by name. Each command has its name (a switch is named for what choosing it does now), where it lives, its shortcut (`keys`: the one table of shortcuts), whether it can be done now and why not, and what it does. The ribbon's buttons, the File page's items and the search all run these, so a thing has one name and one answer wherever it is asked for. |
| `tab_bar.rs` | The tab bar: the logo in its light tile (the app's picture, never drawn here), the tabs (through the unfinished parts' filter, so a hidden tab leaves no gap), the contextual tabs that come with an open file (in front while their ribbon is shown: HOME TOOLS · Tile map while the Map shelf tab is), the search box with its key, the project and area, the chevron. |
| `ribbon.rs` | The ribbon's table types (`Group`, `Slot`, `Shape`, `Control`), the makers the tables use (`big`, `row`, `switch`, `big_list`, `row_list`, `fact`, `unbuilt_at`), and the layout: every width is known before anything is drawn, the groups go left to right, the Play group is pushed to the right edge, and the band scrolls sideways when it doesn't fit (the wheel over it scrolls it). Also the band itself: in its own strip, or dropped over the center while collapsed. |
| `controls.rs` | How a working control is drawn: the large button and the one light one, the small row, words alone, and the list a control opens from its small arrow or a right-click ([decision 0103](../../../../docs/decisions/0103-todays-keys-stay.md)). |
| [`ribbons/`](ribbons/README.md) | One small table per tab. |
| `play_group.rs` | The Play group: Play, or Stop with Pause and Step while the game runs, and Simulate (unfinished). |
| `file_page.rs` | The File tab: the column of items (through the filter) and the page area, which shows the page in front (`file_pages`); until a project is open, Back to editor reads Carry on without a project. |
| `create.rs` | The two kinds of entity the Create group makes that the editor had no one-step way to make: a sprite and a reverb zone. |
| `tests.rs`, `middle_tests.rs`, `saved_tests.rs`, `status_tests.rs`, `picture_tests.rs`, `middle_picture_tests.rs` | The commands' table; the tabs and what each shows; the ribbon's and the middle's measured layout against the tokens; scrolling, collapsing, lists, the Play group, the File page, the grip, the divider, folding and the document tabs, used as a person uses them; the saved frame, read back, repaired and fuzzed; the status bar's words; and the frame's colours sampled from frames drawn for real, each tab against its approved picture. The two picture files also have ignored tests that write the top on each screen, and each tab at 1440 × 900 and 1100 × 700 beside the design's, to a folder to look at. |

[`../shell_reach_tests.rs`](../shell_reach_tests.rs) holds the rule that nothing became unreachable: the old menu bar, item by item, each still a command that can be done, listed by the search, and drawn where its row says.

## Adding to it

- **A new thing the editor can do:** add it to `ShellCommand` (and to `ALL`), give it its words in `command_words.rs` and its `why_not` and `run` in `commands.rs`. It is in the search at once. Put it on a ribbon by adding a line to that tab's table.
- **A control the engine can't do yet:** list it in the table as `unbuilt_at(shape, Entry::Unbuilt(UnbuiltId::..))`. Never draw one by hand ([`../unbuilt/`](../unbuilt/README.md)).
- **A new key or mouse action** needs the project lead's answer first (rule 17 of CONTRIBUTING.md).
