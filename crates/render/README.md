# render

**Layer 1 · Engine**

Draws viewports with wgpu into offscreen images: the backdrop (a calm sky with a horizon), imported models with glTF's full material in the standard, stylized (with outlines) or unlit look, lit by the sun (with a shadow map, also darkening the ground), up to 16 point lights and spotlights, and the sky; drawn in HDR and tone mapped (AgX, ACES or none) with exposure, under the editor's backdrop or a daylight sky, with optional fog (`environment.rs`, [decision 0017](../../docs/decisions/0017-hdr-tone-mapping-sky-and-fog.md)); the ground grid (1 m, 10 m and 100 m lines), the X and Y axes, and small markers where lamps are (these three only with `FrameParams::editor_lines`, off for the game's own view; the grid lies in `FrameParams::grid_plane`, the ground or upright for a flat view from the front or side). `lighting.rs` holds the sun and lamps, in Blender's units ([decision 0014](../../docs/decisions/0014-lights-placed-two-ways.md)).

Phase 9, D1: the pixel stage (`pixel.rs`, `pixel.wgsl`, decision 0062). A 2D game is drawn into a small target (its base resolution plus a pixel each side) by `render`, then `draw_pixels` scales it into a screen-sized `PixelImage` as `pixel_layout` says: **whole steps** (each screen pixel shows exactly one source pixel, bars round the rest) or **fill** (sharp bilinear: only each pixel's last screen pixel blends). The camera's bit of a pixel slides the picture across the margin, in whole screen pixels for whole steps. `PixelLayout` gives the same sums on the CPU (`source_pixel`, `to_screen`, `to_picture`) for tests and for finding where a click lands. `FrameParams::grid_step` spaces the grid (the 2D view's tile size). `read_texture` reads any image back for tests.

Phase 9, D2: sprites (`sprites.rs`, in `viewport.wgsl`). `upload_sheet` puts a sprite sheet's atlas on the card once (`GpuSheet`). `render_scene` takes a `Scene`: the placements, lamps, bolts and `SpriteRun`s (a sheet and its `SpriteInstance`s, 88 bytes each: the frame's corner, a pixel's step across and down in the world, its place in the atlas, flip, tint, flash, outline, where it stands). Each run is one instanced draw of six corners. Pixel art is cut out (a pixel is drawn or not, by `textureLoad`, never filtered), so sprites write depth and need no sorting: the shader draws one standing lower on screen a hair nearer (`FOOT_DEPTH`), so front and behind come free, and a whole metre of height always wins. See-through sprites blend, drawn last in the order given (back to front). Sprites write alpha 0, which the last pass shows as drawn: their colours are never lit or tone mapped. Picking draws sprites by their own pixels too (`request_pick_with_sprites`, `SpritePicks`), so the clear space round one picks what's behind. `FrameStats::sprites` counts them. Phase 9, D4: a sprite flagged `UNDER` or `OVER` is a tile map's layer, drawn by a flat pipeline that ignores depth: under ones right after the sky, before everything, over ones last, over everything (`SpriteLayer`); they blend by their own alpha so empty cells show what's below.

## Purpose

Turn a camera, a few colours and the sun ([`FrameParams`]), plus models placed in the world (`Placement`: a model and where it is) and lamps, into a finished image in a `ViewportTarget`, on whatever GPU device it is given. The editor shows that image in its viewport panel; games will draw through the same crate.

## Must never

- Depend on the editor or any interface crate: games ship without the editor
- Wait for the GPU in the frame loop (only the test helper `read_pixels` waits)
- Hold on to the window or the GPU device: it is handed a device for each call

## Colour

The image is plain 8-bit RGBA; the shaders convert linear colour to sRGB as they write, so it works on GPUs (such as OpenGL ones) that can't reinterpret an image's format. See ARCHITECTURE.md, "Colour in the viewport".

## Tests

`tests/gpu.rs` renders real frames and checks pixels. It skips without a GPU, unless `REQUIRE_GPU=1` is set. Without a graphics card, Mesa's software driver works: `WGPU_BACKEND=gl cargo test -p render --test gpu`.

## Depends on

`assets` (for the model data it uploads), wgpu, glam and bytemuck.

## Status

Phase 1 complete: backdrop and daylight sky, grid, axes, models in three looks, the sun with shadows, lamps, fog, HDR and tone mapping. Phase 3: picking (`pick.rs`): on request, the placements are drawn into an ID image (each pixel: the placement's number and depth) inside the rectangle asked about, and read back without waiting. Phase 5, M6: projectiles (`projectiles.rs`): `render_with_bolts` draws `Bolt`s (head, trail, colour, width: 40 bytes) as camera-facing streaks at least 1.5 pixels wide (wider far ones dimmed a little), all in one instanced draw after the models, added to the HDR image without writing depth (models hide them; they light each other). Phase 5, M5: levels of detail. Each mesh's levels are uploaded with it (sharing its corners, or with their own), and each model knows how far each level strays as a share of its size (`model_lod_errors`). The gather chooses one level per copy, the simplest that strays less than `LOD_PIXELS` (1) on screen, keeping last frame's level within a band so copies at a boundary don't flicker (each view remembers its copies' levels); batches are per level, and `FrameStats::lods` counts copies at each. Picking always uses the full meshes. Phase 5, M4: only what's seen is drawn. Each mesh copy's ball (worked out once per mesh when the model is uploaded, `GpuModel::sphere_of`) is checked against the view's sides, and against where shadows fall swept along the sun's light, in the same jobs that gather the copies (`instances::Cull`); copies are sorted into those in view only, both, and casting only, so the main pass and the shadow map each draw their own. The sun's shadow map is fitted to the view (`sun_view_fitted`): it covers what's in view up to `SHADOW_REACH` (200 m) and takes in what casts into it, moving a whole texel at a time so edges don't crawl. Each copy is 52 bytes (three rows of its placement; the shader works out the normals' matrix from the cofactors), and a frame sends only the runs of copies that changed (`FrameStats::sent_bytes`). Picking draws only what's in view too. Phase 5: gathering the copies runs in jobs (`rayon`, decision 0031): each placement's copies made in parallel, grouped by putting each run's copies into a bucket per batch and joining each batch's buckets in order (the Phase 5 review: no sort of every copy), the same on any number of cores. A placement of one node picks its level of detail from where that node stands. `render` says what it drew (`FrameStats`: copies, draw calls, triangles), and on cards with timestamps times its passes (`timing.rs`, `ViewportTarget::gpu_times`: shadows, models, the last pass), read back a frame or two later without waiting. Phase 2: every mesh copy is an instance in one buffer per frame, each mesh drawn once for all its copies; mirrored copies use pipelines that treat the other side as the front. A placement can draw one node of a model on its own (an unpacked part).
