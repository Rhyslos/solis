# app/src

The program's code: the command line, the window and its frame loop, the GPU hookup, and the slow work (files, imports, updates, sound) done on workers. It holds no feature logic; it connects the editor (`editor` crate) to the engine crates.

**Start reading at** `main.rs`, then `window.rs`.

## The project and its files

| File | What it does | Main items |
| --- | --- | --- |
| `project.rs` | The open project: its asset database, the watcher on its assets folder (each change it reports is looked at on a worker, and what changed handed back by a later `poll`), and the projects Solis knows (decision 0021); notes this build in each project it opens (decision 0086). The editors' savers (`save_frames`, `save_sound_event` and the rest) all find their file through `Projects::place`: a plain path inside the assets (`plain_inside`, the rule `external.rs` keeps to as well) of the saver's own kind, so none writes outside the assets folder; the five whose files have a format version share `save_versioned`. The Library's file changes keep to the same rule before `asset_db` does them: a move (`from` plain, `to` a name in a folder there, `named_inside`), a delete, and a new folder or sound event (`assets_or_inside`: the assets folder itself, or a plain path inside). Only `open` and `bring_in` take a path from anywhere on the computer, chosen by the user in the system's own window or dropped on the editor. Tests in `project_saving_tests.rs`: every saver and file change against paths that stray, and a sweep of made-up paths. | `Projects`, `Opened`, `plain_inside` |
| `known_projects.rs` | Every project the launcher knows (decision 0086): folder, pin, when last opened, the name last read and where it was last exported for playtesting on this computer, up to 200, saved with the settings and read once from the recent list kept before; each one's project file read for the launcher's rows; copying a project and scanning a folder on a worker (`Tidying`). | `KnownProjects`, `Known`, `Tidying` |
| `area_file.rs` | Reading and saving area files, the Open and Save windows, and noticing when the open file changes on disk (decision 0020). | `AreaFiles` |
| `import.rs` | Imports models on a small pool of workers (through the import cache when a project is open), so the window never waits; also the system's Open windows. | `Importer`, `Finished`, `FolderFor` |
| `thumbnails.rs` | The Library's thumbnails: pictures shrunk on a worker, models drawn once on the GPU, on the theme's backdrop (and again when the theme changes). | `Thumbnails` |
| `game_code.rs` | The project's game code on a worker: whenever its assets change, writes the files describing the engine and the project's names to Lust, then reads, checks and turns the project's Lust into Lua, all on the worker. Code that couldn't be checked because an earlier check never finished (`script::NotStarted`) is checked by itself when that one ends; a check that crashes is said as the code's problem, like one given up on. | `GameCode`, `Checked` |
| `play_files.rs` | Files for playing: the input actions (`input.solinput`), the buses (`mixer.solmix`; a damaged one kept as a backup when saved again, an older one copied to the backups), recordings of play (`recordings/*.solrec`) and save games, each read within limits. | `PlayFile`, `RecordingDialog`, `save_game` |
| `check_project.rs` | `--check-project <folder>` (Phase 8, C4): opens a project without the window, gives files just made their sidecars (`settle_new_files`, waiting as the editor would), reads every file, checks the game's code, and plays back `recordings/checks/` in their areas headless, with the sprite sheets, tilesets and tile maps read once (`read_sheets`, `Read`); a plain report, and a failure code if anything changed. Tests in `check_project_tests.rs` (the samples, a changed area, damaged files). | `check`, `Report`, `workbench_for` |
| `upgrades.rs` | Older files as the editor meets them (Phase 8, C1): a Console note when one is opened (it's upgraded in memory), and saving through `asset_db::backup`, which copies the older file first. Every format's example files, in `tests/fixtures/`, are opened by `fixtures_tests.rs`. | `older_note`, `save`, `kept_note` |
| `to_lust.rs` | Moving a project's older files to Lust when it opens (decision 0081): each is written as a Lust data file beside it, checked, its sidecar moved with it and the older file kept in the backups. | `move_older_files` |
| `sound.rs` | Opens the sound card on a worker, using a silent device until it is open or when there is none. `window.rs` asks for it at the top of every frame, before the frame splits into the splash, the editor or an exported game. | `Sound`, `Opener` |
| `playground_sounds.rs` | The playground's sounds, made in code (CC0): footsteps, music, a radio's chatter and a drip, as WAV files, the same every time. | `footstep`, `music`, `radio`, `drip` |
| `game_audio.rs` | The game's sounds each frame: picks and plays what game code asked for through its bus, around the camera, following entities, held while paused and faded on Stop; ducking, mute, solo and `Audio:setVolume` as the buses' levels, and the meters back to the Mixer; `AudioSource` loops, and choosing the most important sounds to hear (S5); the reverb zones the camera is in (S6); only what the listener should hear (S8). | `GameAudio` |
| `sounds.rs` | The project's sound files and sound events in the editor: sounds measured and events read on a worker for the Library and Properties, and listened to through the sound device (an event plays a new pick each press). | `Sounds` |
| `text_files.rs` | The text file shown in Properties, read when it's picked and again when it changes on disk, at most 512 KB, refused if it holds a zero byte. | `TextFiles`, `read_text` |
| `sprites.rs` | The project's sprite sheets (Phase 9, D2): Aseprite files read and packed on a worker, again whenever one is saved, a failed read keeping the last good one; tile maps and the pictures tilesets, atlases and the game's screens use (each up to 64 MB) read on the same workers, the last one read kept until the new one arrives; clips files, animators, tilesets and atlas files (Atlas Crop), small text, read where they're asked for. It is the one owner of what each of those files holds: a file the editor changed is kept as the file the moment it's saved (`saved`), and not read again until it changes on disk. | `Sprites`, `Sprites::saved`, `read_sheet`, `read_tileset`, `read_tile_map`, `read_atlas`, `read_art` |

## How the pieces fit

`main.rs` calls `cli::parse`, then `window::run`, which shows the splash (`startup.rs`) and then the editor. Each frame, `window.rs` asks the editor's `Workbench` to draw itself, passing it a `GpuViewport` (`gpu.rs`) to draw the 3D views, and acts on the actions it returns; anything slow goes to a worker (`import.rs`, `game_code.rs`, `thumbnails.rs`, `sounds.rs`, `sprites.rs`, `updates.rs`) and is picked up between frames.
