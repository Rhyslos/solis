# app

**Layer 3 · App**

The `solis` program: reads the command line, opens the editor window with eframe (winit and wgpu), restores the settings saved last time (panel layout, accent colour, viewport controls), and hands each frame to the editor's workbench.

## Purpose

Wire the engine and the editor together. It owns the window and the GPU device, connects the `render` crate's viewport images to egui (`gpu.rs`, one image per view: the viewport's and the Game panel's), reads model files on background threads with `assets` (`import.rs`), and carries out the editor's actions (quitting, importing, saving and opening areas, the Library's file changes, opening files in their own programs with `opener`). `thumbnails.rs` makes the Library's thumbnails: pictures shrunk on a worker, models drawn once on the GPU. `logger.rs` passes what the libraries write through the `log` facade to the Console: every library's warnings and errors, information only from Solis's own crates. The console's earlier commands are saved with the other settings. `build.rs` builds the logo (`branding/logo.ico`) into the program file on Windows. `src/README.md` lists every file in `src/`.

## Must never

- Hold feature logic: that belongs in the engine or the editor
- Hard-code the program's name outside `branding.rs`

## Depends on

`editor`, `render`, `assets`, `asset_db`, `input`, `updater`, `sound`, eframe, rfd (the system's Open window), opener, log, and on Windows gilrs (gamepads).

## Status

Phase 1: the editor with a drawn viewport, a flying camera, and imported models. Phase 2: projects, area files and assemblies. Phase 3: picking, the Library's thumbnails and file actions, and library messages in the Console. Phase 5: the benchmark (`benchmark.rs`, Help > Make the benchmark…): a project of two fleets of ships (the ship model from `assets::sample::ship_glb`, its sidecar with a fixed ID, an assembly, and `samples/benchmark/assets/main.lst`) in three areas; every assembly in a project is read when the Library is listed, so game code can spawn any; the Game panel's projectiles are handed to the renderer (`render_with_bolts`). Phase 6: the project's input actions read from and saved to `input.solinput` and recordings saved in `recordings/` and opened for replay, and save games written to and read from `saves/` (`play_files.rs`); the first gamepad read each frame with gilrs on Windows only (`gamepad.rs`; elsewhere none, so the Linux checks need no system libraries); the playground (`playground.rs`, Help > Make the playground…): a level made in code (steps, ramps, crates, a moving platform, a character with the ready-made controller and third-person camera), its models from `assets::sample::playground_glb` with fixed IDs, `samples/playground/assets/main.lst`, and its input actions with QuickSave (F6) and QuickLoad (F7). Updates (decisions 0043 and 0045): `startup.rs` runs the splash screen's logic: at least 0.6 s, a check with `updater` while it shows (unless Help > Check for updates when starting is off; saved with the other settings, as is the build skipped with Skip this version), the update question for a newer build, and, for Update now, a download on the splash then closing so its installer opens the new build. `updates.rs` does the rest once the editor is open: Help > Check for updates asks the same question, Update now downloads while you work, and a downloaded installer waits in a slot that `window::run` starts once the window has closed (relaunching after Restart to update). The splash draws the logo from `branding::LOGO_PNG`. `version()` adds the build number to the version. Phase 7, S1: `sound.rs` opens the sound card on a worker, keeps a silent device until it opens (or when there's none), tells the Console once, and tries again every 30 seconds; `sounds.rs` measures the project's sound files on a worker for the Library and Properties (again when one changes) and plays them, streamed from the file, when ▶ or Play is clicked; a sound can't be placed in the scene. Phase 7, S4: the project's buses read with it (`play_files::load_mixer`) and saved by the Mixer (`save_mixer`); `game_audio.rs` mixes them each frame. Phase 9, D1: the project's 2D settings read with it (`play_files::load_pixels`) and saved from Settings > 2D (`save_pixels`); `gpu.rs` draws a view through a 2D camera into a small target and scales it up with the pixel stage (`render_pixels`, decision 0062).
