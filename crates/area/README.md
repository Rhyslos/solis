# area

**Layer 0 · Core**

The area document ([decision 0019](../../docs/decisions/0019-scene-document-now-game-storage-later.md)): entities with stable IDs, names, parents and sibling order, and their components as plain values described by schemas (the `reflect` crate). Also the built-in components: `Transform`, `Light`, `Environment`, `Model`, `Camera` (what the game looks through: its View, perspective or 2D, field of view, near and far, with its projection), and from Phase 6 `RigidBody` (dynamic, kinematic or fixed; mass, damping, gravity, upright, fast) `Collider` (box, sphere or capsule; size, radius, height, centre, friction, bounciness) and `CharacterBody` (a standing capsule moved by game code: height, radius, step height, steepest slope, keeps to the ground, mass; `collider` gives its capsule), which the game's world turns into physics.

## Purpose

Be the one place an area lives while it's edited. The editor, saving and loading, assemblies and undo all work on this document. The running game's fast storage (Phase 3) is built from it when Play is pressed.

- **Built-in components** (`builtin/`) are typed Rust structs that turn into values and back through `reflect::Component`.
- **Components nobody registered** (a newer version, a script that isn't built) are kept untouched, never dropped.
- **Edits** (`Edit`) are the only way the editor changes an area: set a field, add or remove a component, spawn, despawn (a whole subtree), rename, reparent. Applying one returns its inverse ([decision 0022](../../docs/decisions/0022-undo-as-reversible-edits.md)); a list that fails part-way is rolled back.
- **Tree** (`Tree`): the area's tree worked out once (children in order, tree order, the first of some entities, every world matrix in one pass), for a caller to keep until entities are added, deleted or reparented.
- **No loops of parents.** A loop (entities inside each other) can only come from a damaged or hand-merged file, since the edits that would make one are refused. Reading a plain area and expanding a file's assemblies take loops out (`Area::mend_loops`: each loop's entity with the lowest ID moves to the top level, the rest stay under it; `Expander::mended` lists them for the Console), so no area in use has one. Every walk up through parents goes through `Area::ancestors`, which ends in a loop instead of going round, and an entity found in one stands alone at its own Transform, the same in `world_matrix`, `Tree::world_matrices` and the game's world. A parent that isn't in the area is kept as written and counts as the top level everywhere.
- **History** (`History`) keeps undo steps of edits, with the selection before and after (of the caller's type). Steps with the same `MergeKey` in a row merge (a whole drag), keeping only each field's first and last value; a merged step that changes nothing disappears. Steps are shared, so copying a history is cheap, and each step's selections count toward its limit (`Weigh`). History is limited by memory, not by count. `follow(area, played)` makes in a copy what was done in `played` since the copy was taken (steps undone are undone, steps made are made, each undoable), leaving out what no longer fits because `played`'s area was also changed without steps; `hold()` makes `played` keep every step from then on, whatever the limit. The editor uses the pair at Stop, to keep the edits made while playing without what the game did.
- **The tree:** `hierarchy()` and `depth_first()` give every entity's children in one pass; `order_after` and `order_at_end` make sibling orders (short base-36 counters) so new entities go last; `ancestors` walks up through an entity's parents; `world_matrix` adds up parents' transforms.
- **Text** (`text.rs`): areas as Lust-style data blocks ([decision 0020](../../docs/decisions/0020-scene-files-in-lust-style.md)): `write` and `read`, one block per entity sorted by ID, numbers as the shortest text that reads back exactly, unknown components kept, a version line (2; version 1 files are read as they always were, and one from a newer version is refused by its first line), limits checked before keeping anything, every mistake reported with its line. No file access: the app reads and writes the files.
- **Assemblies** (`assembly.rs`): a placed assembly is its root entity (with an `Origin`) plus overrides in the file, and ordinary entities while edited. `Expander` expands copies (IDs from `derive(copy root, path)`, so the same file gives the same IDs), collapses them back to what differs, counts entities before making any and keeps to the limit while making them, refuses loops (naming the chain) and nesting past 16. Overrides whose part is gone are kept as entities, so the count takes in every override that doesn't remove its part. A change to a part's parent says one of three things (`text::ParentChange`): left where the assembly has it, moved under an entity, or moved out to the top level (`parent = "";`, area files' version 2); a part gone from the assembly hangs under its copy until one of the other two is said. A part is placed where its copy put it: one moved isn't taken along when the part the assembly has it under is removed from the copy. `despawn` gives the edits that delete entities, first making ordinary entities of parts that a deleted copy leaves behind (moved out from under its root), so the area saved is the area opened. `set_in_file` is Apply to assembly.
- **2D settings** (`pixels.rs`, Phase 9, D1): a project's base resolution, pixels per unit, tile size and scaling, read from and written to `pixels.solpix` (a settings file, format 1), values out of range brought in with a note.
- **Sprites** (`builtin/sprite.rs`, Phase 9, D2): the `Sprite` component, one frame of a sprite sheet lying on the ground at the entity, standing on its pivot slice, with flip, tint, flash, outline and see-through; from D3, the clip it plays (Clip, Playing, Speed, Clip time).
- **Animators** (`builtin/animator.rs`, Phase 9, D3b): the `Animator` component: an animator file (`.solanim`) that chooses the Sprite's clip, the state it starts in (and, while playing, is in), and a speed.
- **2D colliders** (`builtin/collider_2d.rs`, decision 0071): the `Collider2D` component, a shape on the ground for 2D physics, in pixels: a circle or a box, offset across and up, solid and still or a character game code walks.
- **Parallax layers** (`builtin/parallax.rs`, [decision 0094](../../docs/decisions/0094-parallax-layers.md)): the `Parallax` component, which makes the entity's Sprite a layer moving with the camera at its own speed (scroll across and up), repeated if wanted, behind everything or in front; `Parallax::offset` says how far it goes along with the camera.
- **Tile maps** (`builtin/tile_map.rs`, Phase 9, D4): the `TileMap` component: a tile map file (`.soltilemap`) placed with its top-left corner at the entity. `settings::read_block_settings_within` reads a block settings file with a cap on its blocks, for files as big as a map.
- **Brushes** (`builtin/brush.rs`, Tools 1a, B1, decision 0111): the `Brush` component, a shape made in the editor: what it was made as (`mesh::Shape`), Solid, and its mesh (`mesh::Mesh`, shared) written as three lists of numbers (`points`, `faces` with each face's count first, `materials`), whose counts are checked against `MAX_POINTS`, `MAX_FACES`, `MAX_CORNERS_PER_FACE` and `MAX_CORNERS` before anything is made; a mesh that breaks one, or a face naming a point twice or one that isn't there, reads as an empty brush (`Brush::damaged`). Area files are version 3 from it: lists of more than `text::NUMBERS_PER_LINE` numbers are written over several lines. `points_of` gives a mesh's points list alone: editing a brush's insides changes only that one (B3).
- **A new area** has a Sun and an Environment (the sun, sky and fog live in each area).

## Must never

- Hold code from a game or a script library: only values, so swapping a library never leaves stale types behind.
- Drop data it doesn't understand.
- Depend on the GPU, the window, files or the editor.

## Depends on

`reflect`, `mesh` (a brush's mesh and its shapes), glam, and the Lust compiler (`lust`), which reads Lust data files (`lust_data`).

## Status

Phase 2 complete: the document, the built-in components, edits and undo history, the tree, and the text format. Phase 7, S2: settings files (`settings.rs`) in the same text style, for sound events and later the mixer. Phase 9, D3b: settings files with blocks (`word ID { key = value; … }`) as well as fields, for animators.

Usable first, L1 (decision 0081): `lust_data` writes and reads Lust data files: exact numbers and text, a header that fetches the format's classes from `solis/data/`, and `write_blocks`/`read_blocks`, which keep a settings file's fields and blocks as Lust things and read them back into the same blocks. Reading goes through `lust::read_values_with`, which runs nothing, after `lust_guard` has refused what Lust can't finish checking: a file that declares a class (two with one name leave Lust working for ever), text holding a value in `{ }`, or a long run of `!`. Then `lust_check` lets through only what a data file holds, each piece checked against the file's own classes in one pass (a `fetch` of them, `lock` values of numbers, text, options, lists and `new` things of the right types, at most 64 of them and 32 deep, and `end`): Lust has no budget, and a file full of mistakes took it minutes, so what reaches it now is read in time that grows only with the file's length. Lust also keeps about 100 bytes for every piece of a file while it reads it, so a file with more than 12 million pieces (numbers, texts, names and symbols) is refused as too big to read. `lust_data::fits` asks the same of text about to be written (its length and its pieces, the reader's own limits), for a writer whose data can outgrow its reader: a tile map's writer refuses to write what wouldn't be read back. A file whose text holds a control character (other than a line break or a tab) is refused too: the writer leaves those out, so no text is read that wouldn't be written back as itself. `script::code` guards game code with the same module. `area` depends on `lust` for it.
